# Inter-Batch Resume Protocol

Protocol version: 1

## Resume package

Provide:
1. The latest session-state declaration.
2. The standing standards checklist.
3. The descriptive batch name to resume.
4. Any changed constraints.
5. The relevant unresolved traceability entries.

Do not re-paste all completed code by default.

## Intake procedure

- Validate the state-declaration format and scope.
- Separate delivered work from verified work.
- Preserve all explicit limitations.
- Confirm repositories, destinations, and language constraints.
- Identify the next requested artifact.
- Check whether its required source is present in the receiving context.

## Missing source

If implementation details are absent:
- do not reconstruct code from the state marker;
- request the exact required file or bounded sections;
- state which comparison or edit cannot yet be established;
- continue work that is independent of the missing source.

## Continuation

- Do not automatically re-emit or modify completed artifacts.
- Bind changes to the actual supplied baseline.
- Retain prior protective defaults.
- Record integration corrections in the ledger.
- Update traceability dispositions with evidence.
- Register new schemas and vocabulary versions.
- State tests executed versus tests supplied.

## Conflicting resume records

- Do not silently select the more favorable record.
- Report the conflict.
- Preserve known adverse findings.
- Require clarification or source evidence before baseline-sensitive changes.

## End-of-batch update

Post the fixed session-state format.
Include delivered work, verification, next batch, standards, repositories,
destinations, pending hardening, and continuity limitations.

## Privacy boundary

No private system inventory, identity proof, credentials, neural data, or raw
scene content is required merely to resume engineering work.
