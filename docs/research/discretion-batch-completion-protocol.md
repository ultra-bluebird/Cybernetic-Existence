# Discretion and Non-Interference Batch Completion Protocol

Protocol version: 1

## Scope

Complete and integrate:
- Companion-system discretion boundary.
- Non-interference contract.
- Non-actuating research adapter.

## Exact sequence

### Baseline intake

- Identify the exact earlier code and review context.
- Preserve existing unresolved findings.
- Do not imply live inspection or attempted-command tests occurred.

### Companion discretion

- Audit prompt metadata without collecting private answers.
- Keep optional private prompts visible as disclosure-pressure findings.
- Bind UNKNOWN resolution to the exact reviewed prompt.
- Preserve adverse proposed classifications during conflicts.
- Separate ordinary service from transaction-specific data requirements.
- Provide task-preserving alternatives and actual human-fallback requirements.
- Never authorize service denial from an audit result.

### Non-interference

- Inventory privileges, equipment interfaces, command paths, file writes,
  log writes, credentials, IPC, dependencies, indirect dispatch,
  side-effect-capable requests, background/recovery, and diagnostics.
- Require context- and artifact-bound inspection evidence.
- Record additional-path discovery.
- Preserve adverse evidence pending resolution.
- State precisely what the module does and does not enforce.

### Research adapter

- Consume approved aggregate snapshots, not equipment connections.
- Expose no credential, command, or operational configuration interface.
- Distinguish analysis output from control recommendations.
- Enforce bounded data and arithmetic.
- Keep source validation, model validation, and privacy-release review separate.
- Define the intended downstream consumer as local research review.
- Do not describe an advisory enum as physical actuation.
- Do not describe lack of a local actuator method as deployment-wide proof.

### Tests

Supply one complete test file per source.

Include:
- Optional and required private prompts.
- Unresolved, expired, and mismatched prompt resolutions.
- Hidden or indirect command paths.
- Self-review versus independent-review declarations.
- Missing, conflicting, stale, and adverse inspection records.
- Attempted-operation success/failure/silence in simulation.
- Material-change invalidation.
- Aggregate accounting errors and discontinuous windows.
- No automatic equipment action or export.

Live attempted-command tests require a separately approved isolated procedure.

### Integration

- Define process privileges and approved data ingress.
- Identify independent inspection and negative-test responsibility.
- Explain authentication of evidence if implemented.
- State whether logs exist; strict no-write qualification includes log writes.
- Keep operational execution outside the research adapter.
- Preserve ordinary service and assistance during qualification failure.

### Batch close

- Provide models, complete files, tests, integration notes, and limitations.
- Update ledger, registry, and traceability.
- Distinguish supplied tests from execution.
- End with the fixed session-state declaration.

## Exit conditions

The batch can be delivery-complete without being independently inspected.

A non-actuation claim remains scoped to the exact implementation and deployment
evidence. No result grants control over public or private infrastructure.
