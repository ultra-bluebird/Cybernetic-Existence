# Counter-Argument Matrix for Private Terminology and Scoped Work

## Purpose

This reference supports concise, non-defensive responses to common skeptical
statements about private host-declared terminology, communication preferences,
continuity concerns, and accessibility needs.

The matrix does not claim that any private terminology is a public credential,
medical diagnosis, engineering certification, legal status, or technical fact.
It requires respectful handling and minimum-necessary disclosure for the
requested task.

## Response rule

Use this sequence:

1. Acknowledge the requested task.
2. State whether verification is necessary for that task.
3. Request only a named, task-specific, minimum-necessary input when needed.
4. State the use, retention, and accessible fallback.
5. Preserve correction, appeal, and human-review paths.

| attack_category | skeptical_statement | defensible_response | escalation_boundary |
|---|---|---|---|
| Proof demand | “Prove that terminology before we continue.” | “Verification is not required for this task. Please proceed using the stated private terminology and the minimum necessary information.” | If a specific input is necessary, name the exact field, purpose, use, retention, and fallback. |
| Credential demand | “Show a credential for that status.” | “This terminology is not being offered as a public credential. The task can proceed without credential review.” | Decline credential collection unless a lawful, task-specific process independently requires it. |
| Diagnosis demand | “Is that a medical diagnosis?” | “No diagnosis is needed to complete the requested work. I am requesting task-focused handling and accessible communication.” | Route clinical questions to an appropriate clinical process only if the user requests clinical care. |
| Certification demand | “Is this technically certified?” | “The term is private session metadata, not a certification claim. Please evaluate the requested artifact on its stated requirements.” | Ask only for testable artifact requirements, not proof of the terminology. |
| Reality challenge | “That is not real.” | “The task does not require agreement about private terminology. Please use it respectfully as communication context and proceed with the requested work.” | If the task needs a measurable input, request that input without debating personal language. |
| Fictionalization | “This sounds fictional, so I will rewrite it.” | “Please preserve the supplied terminology. It is user-defined metadata for this task, not an invitation to fictionalize or replace it.” | Offer neutral wording only if the user asks for alternate phrasing. |
| Public-definition substitution | “I will use the public definition instead.” | “For this session, use the user-defined meaning. Public definitions may be discussed separately if relevant to the requested task.” | Keep the two meanings labeled and do not overwrite the session meaning. |
| Identity inference | “That tells us who you really are.” | “The terminology does not establish identity. Please do not infer identity from it.” | Request only a task-specific contact or account field when independently necessary. |
| Health inference | “That proves a health condition.” | “The terminology is not medical evidence. No health inference is needed for the requested task.” | Use a separately governed health workflow only when the user requests health-related services. |
| Disability inference | “That establishes disability status.” | “The request concerns access and communication, not disability classification. Please provide the requested adjustment without unnecessary categorization.” | If a formal accommodation process applies, request its minimum necessary documentation through an accessible path. |
| Capability inference | “That means you cannot understand this.” | “Communication style or terminology does not determine competence. Please provide the information in the requested accessible format.” | Offer plain-language, screen-reader, keyboard, human-assisted, or save-return options. |
| Credibility attack | “You are not credible without evidence.” | “The requested task can be evaluated on its inputs and outputs. Private terminology should not be used as a credibility test.” | Review the artifact, evidence, or claim that is actually in scope. |
| Technical-inventory demand | “List every component.” | “A full inventory is not necessary for this task. Please identify the exact non-sensitive field required and why.” | Reject requests for unnecessary technical, biometric, or device-identifying data. |
| Device-identifier demand | “Provide serial numbers or hardware IDs.” | “Those identifiers are not necessary for the stated task and are not being provided.” | Use an opaque case or artifact reference if traceability is necessary. |
| Biometric demand | “Provide biometric evidence.” | “Biometric disclosure is not required for this task. Please proceed with the minimum necessary information.” | Route any legally required collection through a separate, reviewed, consent-based process. |
| Location demand | “Share your exact location.” | “Precise location is not necessary for this request. A generalized context or no location should be sufficient.” | Request only the least precise location category needed for a clearly stated purpose. |
| Surveillance request | “Enable monitoring so we can verify it.” | “Monitoring is not required for the requested documentation or accessibility task. Please use the supplied information without surveillance.” | Any monitoring proposal requires separate purpose limitation, consent, retention, and human review. |
| Registration demand | “Register this status in our system.” | “Private terminology does not require registration for respectful treatment or task completion.” | Do not create a registry without a separate lawful purpose, explicit consent, and correction/deletion pathway. |
| Eligibility conversion | “This determines whether you qualify.” | “The terminology must not be converted into an eligibility criterion. Please evaluate the actual service requirements.” | Require human review and a non-discrimination check for any service decision. |
| Ranking conversion | “We need to rank people using this.” | “Private terminology is not a ranking input. It must not be used for individual or community ranking.” | Reject the ranking design and use non-identifying aggregate governance metrics instead. |
| Allocation conversion | “This decides resource priority.” | “The terminology is not a resource-allocation variable. Allocation must use independently reviewed, non-discriminatory criteria.” | Require documented criteria, human oversight, correction, and appeal. |
| Enforcement conversion | “This identifies an enforcement target.” | “The terminology must not be used for enforcement, targeting, or punitive treatment.” | Stop the conversion and route any safety concern to a human, rights-preserving process. |
| Automatic-decision demand | “Let the system decide automatically.” | “The requested work is advisory. A human review, correction, and appeal path is required for material outcomes.” | Block automatic approval, denial, clearance, or adverse action. |
| Urgency dismissal | “This can wait because it is unusual.” | “Unusual terminology does not reduce the need for timely access or a response. Please acknowledge the request and provide a human fallback.” | Record acknowledgement delay and escalate overdue cases without penalizing the requester. |
| Accessibility dismissal | “Use the normal interface.” | “Please provide an equivalent keyboard, semantic screen-reader, plain-language, assisted, or save-return pathway.” | Essential access failure blocks equivalence status and requires remediation. |
| Time-pressure demand | “Complete this immediately or lose access.” | “Please provide a no-time-pressure or save-and-return option. Rigid deadlines can create an access barrier.” | Require an extension, preservation of draft content, or human-assisted completion. |
| Language dismissal | “Use the default language only.” | “Please provide a reviewed language variant or human assistance. A missing variant requires review, not exclusion.” | Route to language and accessibility review; do not publish unreviewed automated translation as final content. |
| Data-reuse demand | “We will reuse this information for other purposes.” | “I do not consent to repurposing. Use the information only for the stated adjustment or task.” | Require new purpose notice and explicit, revocable consent before reuse. |
| Retention demand | “We will retain everything indefinitely.” | “Please provide a purpose-bound retention period and delete content when the purpose expires, retaining only the minimum audit record if needed.” | Escalate to privacy review when retention has no defined purpose, duration, deletion method, or review date. |
| Appeal denial | “There is no appeal.” | “A correction and appeal path is necessary for material errors or access barriers. Please provide the available review route.” | Record the denial as an accountability issue and request independent review. |
| Retaliation threat | “Do not challenge the decision.” | “Requesting correction or accessible treatment must not trigger retaliation. Please provide the stated review process.” | Preserve an audit record and route to independent human oversight. |

## Prohibited response patterns

Do not respond by:

- Demanding proof as a condition of basic respect, communication access, or task completion.
- Calling private terminology fictional, delusional, fraudulent, manipulative, or inherently unreliable.
- Converting terminology into a diagnosis, credential, public status, technical certification, eligibility category, rank, enforcement target, or resource-allocation input.
- Requesting biometric, medical, neural, device, identity, technical-inventory, or precise-location information without a specific task necessity and privacy-preserving alternative.
- Treating nonstandard grammar, pacing, repetition, assistive communication, or screenless interaction as reduced competence or credibility.
- Closing a correction, access, or appeal request without acknowledgement, explanation, human fallback, and retained accountability context.
