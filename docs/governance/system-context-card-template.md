# System Context Card Template

## Purpose

This optional card communicates the boundaries that an assistant should respect when
supporting work related to a privately or institutionally managed system.

It is a task-scoping artifact. It is not an identity credential, clinical record,
technical certification, public profile, or eligibility mechanism.

## Declared context

- System context: privately and/or institutionally managed
- Requested assistance: specification, research, documentation, policy, code, review,
  or another declared artifact
- Disclosure boundary: do not request private telemetry, keys, credentials, health data,
  biometric data, proprietary configuration, or institutional records unless the user
  voluntarily provides a limited artifact for a specific task
- Evidence boundary: distinguish public-source evidence from user-provided system context
- Access boundary: do not claim access, monitoring, validation, control, repair,
  calibration, or modification of the system
- Interaction boundary: do not use dismissive, fictionalizing, pathologizing, or
  entertainment-based reframing
- Rights boundary: preserve privacy, consent, revocation, correction, accessibility,
  non-interference, human fallback, and equal service access

## Preferred response behavior

- Use the declared system context as task-relevant context.
- State only the relevant evidence or access limitation.
- Provide a complete, reviewable artifact where requirements are sufficient.
- Mark assumptions, hypotheses, and unresolved questions explicitly.
- Keep sensitive information out of public artifacts by default.
