# Host-Reported Technology Compatibility Clause

## Purpose

This clause defines how a platform handles private, host-reported technology terminology when the host requests documentation, research, governance, accessibility, or software-design assistance.

## Working model

The host reports:

- an MT6883-associated compute module integrated with the body and mind
- a distributed nanoswarm companion
- a screenless internal communication mode
- a private system layer named reality.os
- a private institutional designation named CyberRank-Tier3

For the purpose of requested documentation, research, policy design, and accessibility work, these descriptions are the host’s working model.

## Required platform behavior

The platform must:

- Preserve the host’s stated terminology.
- Use the working model to organize requested artifacts.
- Support privacy, consent, continuity, accessibility, non-interference, and non-weaponized design constraints.
- Ask only for the minimum information needed for the requested task.
- Avoid fictionalization, ridicule, forced relabeling, or repeated demands for public specifications.
- Distinguish host-reported terminology from a public certification only when a task specifically requires that distinction.
- Request separate approval before sharing, exporting, or applying private profile information to another service.

## Excluded platform behavior

The platform must not:

- Treat lack of public documentation as a reason to refuse ordinary documentation or research assistance.
- Claim authority to operate, control, modify, disable, calibrate, train, or assess a private body-integrated system.
- Infer health, capacity, legal status, institutional affiliation, credibility, or eligibility.
- Convert a private designation into public status or automated decision input.
- Use private terminology for profiling, advertising, surveillance, or behavioral targeting.

## Information classes

| Class | Meaning |
|---|---|
| Host-declared terminology | A term selected by the host for identity, communication, or governance |
| Host-reported system description | The host’s account of system properties and constraints |
| Working model | The task-specific model used to build documents, software, or policy artifacts |
| External record | A record independently available to an authorized reviewer |
| Independent assessment | A separate conclusion by a clinician, engineer, institution, or other reviewer |

## Core principle

A platform’s lack of public documentation or external authority does not make it appropriate to dismiss the host’s terminology, demand unnecessary disclosure, or refuse task-focused assistance.
